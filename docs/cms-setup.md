# ระบบหลังบ้าน — เฟส 1: แก้ข้อความและรูปภาพได้ทุกหน้า

## แนวคิดที่เลือกใช้ และเหตุผล

เนื้อหาของเว็บนี้เป็น HTML เขียนมือ inline style ล้วน อยู่ใน `web/app/_content/`
การแปลงทั้ง 35 หน้าเป็นบล็อก JSON ก่อนถึงจะแก้ได้ จะใช้เวลาหลายสัปดาห์และเสี่ยงทำดีไซน์พัง

เฟสนี้จึง **ไม่แตะ HTML เลยแม้แต่ไบต์เดียว** แต่แทรกชั้นกลางเข้าไปแทน:

```
ไฟล์ HTML ต้นฉบับ ──┐
                    ├─► applyOverrides() ─► HTML ที่เสิร์ฟจริง
ค่าที่ลูกค้าแก้ ────┘     (ตัดต่อตามตำแหน่ง byte)
   (Supabase)
```

- `extractBlocks()` เดิน DOM แล้วแจกกุญแจถาวรให้ทุกจุดที่แก้ได้ — ข้อความ, `<img src>`, และรูปพื้นหลังใน `style`
- บล็อกที่หลังบ้านโชว์ = ลูกตรงของ wrapper ในไฟล์ ซึ่งตรงกับ section ที่คนเขียนเว็บแบ่งไว้อยู่แล้ว
- `applyOverrides()` **ตัดต่อสตริงตามตำแหน่ง byte** ไม่ serialize DOM กลับ ทุกไบต์ที่ไม่ได้ถูกแก้จึงเหมือนต้นฉบับเป๊ะ

ตัวเลขจาก `npm run cms:audit`: **35 หน้า · 3,669 ช่องข้อความ · 341 ช่องรูป**

### กุญแจของช่อง

```
fragment  = ชื่อไฟล์ใน _content   เช่น "home.html", "products/thinner-2k.html"
field_key = ตำแหน่งในไฟล์นั้น      เช่น "3/0.1.2#t0" (บล็อก 3 → เส้นทาง DOM → text node 0)
```

ค่าผูกกับ **ไฟล์** ไม่ใช่ **หน้า** — `_product-head.html` ใช้ร่วมกันทั้ง 14 หน้าสินค้า
แก้เมนูครั้งเดียวจึงมีผลทุกหน้าที่ใช้ไฟล์นั้นจริง

เก็บ `source_hash` ของข้อความต้นทางไว้ด้วย ถ้านักพัฒนาแก้ HTML ทับทีหลังจนตำแหน่งเลื่อน
hash จะไม่ตรง ระบบจะ **ไม่ทับ** และรายงานเป็น stale — ยอมให้เห็นของเดิมของนักพัฒนา
ดีกว่าเอาข้อความลูกค้าไปแปะผิดที่

## ตั้งค่าครั้งแรก

### 1. สร้างโปรเจค Supabase

supabase.com → New project → เลือก region **Southeast Asia (Singapore)**

### 2. รัน migration

Dashboard → SQL Editor → รันไฟล์ใน `supabase/migrations/` **ตามลำดับเลข** — 0001, 0002, 0003

สร้างให้: ตาราง `cms_users`, `content_overrides`, `content_revisions`, `media`,
view `published_content` (เปิดให้อ่านเฉพาะค่าที่เผยแพร่แล้ว), storage bucket `media`, และ RLS ทั้งชุด

> 0002 กับ 0003 คือการรัดกุมเพิ่มหลังรัน advisor — ย้ายฟังก์ชัน security definer ออกจาก
> schema ที่เปิดให้ API, เปลี่ยน view เป็น security invoker แล้วคุมด้วย column-level grant
> แทน และถอนสิทธิ์เขียน view ที่ default privileges แจกมาให้ ห้ามข้าม

**โปรเจคนี้รันครบทั้ง 3 ไฟล์แล้ว** (project ref `tdkkuliwwnhebpwitcfr`) — ขั้นนี้ทำเฉพาะตอนตั้งโปรเจคใหม่

### 3. ตั้ง environment variables

Project Settings → API แล้วใส่ทั้งใน `web/.env.local` และใน Vercel (Settings → Environment Variables):

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGci...
```

> ไม่ต้องใช้ service role key — ทุกอย่างวิ่งผ่าน anon key + RLS

### 4. สร้างผู้ใช้คนแรก

Authentication → Users → **Add user** (ใส่อีเมล + รหัสผ่าน, ติ๊ก Auto Confirm User)

จากนั้นให้สิทธิ์เข้าหลังบ้านใน SQL Editor:

```sql
insert into public.cms_users (id, email, display_name, role)
select id, email, 'ชื่อที่จะให้แสดง', 'admin'
  from auth.users where email = 'อีเมลที่เพิ่งสร้าง';
```

**ล็อกอิน Supabase ผ่านอย่างเดียวยังเข้าไม่ได้** ต้องมีแถวใน `cms_users` ด้วย
ป้องกันกรณีเปิด public signup แล้วมีคนสมัครเข้ามาเอง

### 5. เข้าใช้งาน

`/admin` — ยังไม่ตั้งค่าจะขึ้นหน้าบอกวิธีทำ ไม่ใช่จอขาว

## การใช้งาน

| หน้าจอ | ทำอะไร |
|---|---|
| `/admin` | สรุปจำนวนช่องที่แก้ได้ · ร่างที่ค้าง · รายการแก้ล่าสุด |
| `/admin/pages` | รายการ 35 หน้า พร้อมสถานะ "มีร่าง N จุด" |
| `/admin/pages/<key>` | หน้าแก้ไข 3 แผง: บล็อก · ตัวอย่างจริง · ฟอร์ม |
| `/admin/media` | คลังรูป — รูปเดิมใน `public/images` + ที่อัปโหลดใหม่ |

**ร่าง vs เผยแพร่** — "บันทึกร่าง" เขียนลง `draft_*` เท่านั้น เว็บจริงไม่ขยับ
กด "เผยแพร่" ถึงจะย้ายไป `published_*` แล้วล้าง cache ของหน้าที่เกี่ยวข้อง

**ตัวอย่างในหน้าแก้ไข** คือหน้าเว็บจริงที่รันสคริปต์ชุดเดียวกับหน้าบ้าน คลิกบล็อกไหน
ในตัวอย่างก็เด้งไปเปิดฟอร์มของบล็อกนั้น ลิงก์ทุกอันถูกกันไม่ให้พาออกจากตัวอย่าง

## ข้อจำกัดที่ต้องรู้

1. **เมนูกับส่วนท้ายเป็นคนละชุดในแต่ละหน้า** — เว็บนี้ก๊อป header/footer ไว้ในไฟล์ของแต่ละหน้าเอง
   แก้เบอร์โทรบนหน้าแรกจึงไม่ลามไปหน้าอื่น จะแก้จริงต้องรอเฟส "ตั้งค่าเว็บไซต์"
   ที่ดึงค่าร่วมออกมาไว้ที่เดียว
2. **หน้าบทความ** แก้ได้เฉพาะเนื้อบทความ — เมนูกับส่วนท้ายประกอบใน `_shell.js`
   ด้วย template string ไม่ใช่ไฟล์ HTML
3. **เพิ่ม/ลบ** สินค้า บทความ หรือบล็อกยังทำไม่ได้ในเฟสนี้ — แก้ของที่มีอยู่ได้อย่างเดียว
4. **ยังไม่มีหน้าใบขอราคา** — lead ยังยิงออก `LEAD_WEBHOOK_URL` เหมือนเดิม

## เครื่องมือ

```bash
npm run cms:audit    # ตรวจว่าอ่านครบทุกหน้า และทับค่าเดิมกลับแล้ว HTML ตรงต้นฉบับทุก byte
```
